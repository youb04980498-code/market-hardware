# UnoPim infrastructure

The root Compose file includes this upstream UnoPim definition. All services run in the `market-hardware` stack, with a dedicated PIM PostgreSQL database, Redis, Elasticsearch, application, queue worker, scheduler and Mailpit.

Upstream source: https://github.com/unopim/unopim/blob/3.x/compose.yaml

Local credentials are in the ignored `.env` here. Follow the root [Cold Start guide](../../docs/COLD_START.md): its preparation helper creates this file with a generated database password and shared application key before Compose runs. Never replace these values for initialized volumes.

UnoPim: http://localhost:8000/admin (use this hostname to match APP_URL)
Mailpit: http://localhost:8025

Create a human administrator using the interactive `docker compose exec unopim php artisan unopim:user:create --admin` command after the application is healthy. Old `.local/unopim-admin-credentials.txt` notes belong to the original installation and are not generated by the fresh-clone procedure. The OAuth integration robot is provisioned separately by `scripts/configure-catalog.py`. Images are pinned by digest.

First startup initializes the separate PIM database through the pinned web entrypoint. Do not run `unopim:install` as repair: it invokes `migrate:fresh`. Product-sync subsequently publishes explicitly approved, versioned PIM products into MongoDB and validated compatibility relationships into Neo4j. Full stack initialization requires the ordered root guide, not `docker compose up -d` alone.
