# ADR 0004: One frontend with published API authority

Decision: one React application, router, in-memory Auth implementation and Vite build under frontend. Use ecommerce-react as the storefront foundation (cart, stepper, product-card structure, store shell, route splitting and i18next integration); selectively reuse the dashboard Card and Table code, plus sidebar/inset/Outlet composition. Preserve both MIT notices in the served public/licenses directory. No upstream git metadata, demo database, mock service worker, fake reviews/coupons/shipping, fake analytics or payment processors are imported.

Consolidate on React 19.3.1, Vite 8.3.5, TypeScript 6.0.3 and Tailwind 4, with exact dependency versions and package-lock. Storefront Vite 6/TypeScript 5 and dashboard Vite 8/TypeScript 6 manifests are not merged. Native form validation avoids Formik/Yup; published contracts replace demo Zustand Auth/Orders; MSW/Chance and unrelated Tiptap/blog/tickets are omitted. Recharts is deferred until real Analytics endpoints exist.

Access/refresh tokens stay in JavaScript memory. The backend offers bearer JSON tokens, not HttpOnly cookie sessions. Persisting refresh tokens in localStorage would unnecessarily increase exposure. A full reload requires login, with safe internal redirect back to the requested route. API 401s use single-flight refresh rotation; logout immediately clears local credentials. Server Auth still enforces every privileged action. No credentials or owner secrets are embedded in frontend build variables.

Persist only product IDs, quantity and clearly labelled price estimates in the local cart. Checkout revalidates with Orders, then stores its immutable request/body/user identity and random idempotency key in tab sessionStorage before POST. Network failure retains that identity; retry never invents another payment. Accepted orders clear the cart and navigate to persisted status. Incomplete states always remain pending, including after an uncertain capture. GET order polling is read-only and does not overlap.

Nginx serves static assets and SPA deep links without host-published ports. Existing Traefik routes keep API/GraphQL precedence; fallback excludes /api, /graphql, /internal and /health. A frontend-only Compose profile preserves other profiles, volumes and services. No database migrations or Phase 4 business changes are required.

UI UX Pro Max was installed at the user's explicit request and its complete SKILL.md and relevant references were read. The initial premium query matched Apple glass/luxury fashion and was rejected as off-topic; the narrower electronics/ecommerce query matched the E-commerce category. Its verified output is retained under docs/design-system. Page overrides document restrained forest/neutral tokens and system sans typography for the requested retail aesthetic, without unrelated motion or unverifiable social proof.
