# Phase 8 data catalogue and lineage

Dataset metadata is versioned here; actual update times are `observed_at`, Delta history timestamps and `/api/analytics/pipeline/status` release/snapshot metadata. These are not assumed from file modification dates. Analytics owns transformations; domain services retain source ownership. Source-reader access is explicit column grants; operational services never join another service schema. The existing read-only Analytics export exception is documented in ADR0005.

Four-zone mapping: Raw transport/snapshot audit ? Staging normalization, pseudonymization and invalid-row separation ? Curated harmonized Delta entities/events ? Consumption reconciled aggregates and immutable release manifests ? restricted PostgreSQL serving pointer ? Analytics REST/React. A successful serving pointer requires committed Delta plus zero reconciliation differences. Object store is MinIO; table format Delta/Parquet. Staging normalizes the same authorized snapshot projection before Curated, so no direct identifiers are newly introduced by that boundary.

No email is exported into staging. `customer_key` uses a stable HMAC key held only in ignored .env, so joins work without publishing direct customer identifiers. Changing that key requires a controlled migration, not an ad hoc restart. Arbitrary historical raw event payloads remain restricted; their technical/commercial retention is separate from seven-day application logs.


Technical fixtures are retention-aware: once a successful weekly purge has been recorded, replay will not recreate expired source application logs. Their tracked source CSV is still available; no commercial entity is subject to that filter.
